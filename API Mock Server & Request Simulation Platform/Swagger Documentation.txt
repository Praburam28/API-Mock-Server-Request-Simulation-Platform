# Swagger / OpenAPI Documentation

## API Mock Server & Request Simulation Platform

---

## 1. Overview

The API Mock Server & Request Simulation Platform provides interactive API documentation using **FastAPI Swagger/OpenAPI**.

Swagger UI allows developers to:

* View available API endpoints
* Understand request parameters
* View request and response schemas
* Test APIs directly from the browser
* Authenticate using JWT
* Test protected endpoints
* Verify HTTP status codes
* Test validation and error responses

---

# 6. Register User

## Endpoint

```http
POST /auth/register
```

### Purpose

Creates a new user account.

### Request Body

```json
{
  "username": "testuser",
  "email": "testuser@example.com",
  "password": "Test@12345"
}
```

### Example

In Swagger:

```text
Authentication
    ↓
POST /auth/register
    ↓
Try it out
    ↓
Enter request body
    ↓
Execute
```

### Successful Response

HTTP Status:

```text
201 Created
```

Example:

```json
{
  "id": 1,
  "username": "testuser",
  "email": "testuser@example.com",
  "is_active": true
}
```

### Possible Errors

#### Username already exists

```text
409 Conflict
```

Example:

```json
{
  "detail": "Username already exists"
}
```

#### Email already exists

```text
409 Conflict
```

Example:

```json
{
  "detail": "Email already exists"
}
```

#### Invalid request

```text
422 Unprocessable Content
```

```text

    ↓
POST /auth/login
```

# 16. Dynamic Mock Endpoints

The platform dynamically exposes configured mock endpoints.

Example definitions:

```text
GET /mock/users

POST /mock/orders

GET /mock/products/{id}
```

The actual available dynamic endpoints depend on the API definitions stored in the database.

They are **not hardcoded** into the FastAPI source code.

---

# 17. Dynamic GET Endpoint Example

Suppose a user creates:

```text
Method:
GET

Path:
/mock/users
```

The platform exposes:

```http
GET /mock/users
```

The configured response is returned when the endpoint is called.

Example:

```json
{
  "users": [
    {
      "id": 1,
      "name": "John"
    },
    {
      "id": 2,
      "name": "Jane"
    }
  ]
}
```

---

# 18. Dynamic POST Endpoint Example

Suppose the user creates:

```text
Method:
POST

Path:
/mock/orders
```

The endpoint becomes:

```http
POST /mock/orders
```

A request body can be configured through the request schema.

Example:

```json
{
  "product_id": 101,
  "quantity": 2
}
```

The configured mock response is returned.

---

# 19. Path Parameters

Dynamic endpoints can contain path parameters.

Example:

```text
GET /mock/products/{id}
```

Request:

```http
GET /mock/products/100
```

The value:

```text
100
```

is supplied as the `id` path parameter.

---

# 20. Request Parameters

Mock API definitions can configure request parameters.

Example:

```text
GET /mock/products
```

Query parameters:

```text
page
limit
category
```

Example request:

```http
GET /mock/products?page=1&limit=10&category=electronics
```

The incoming parameters can be validated against the configured request schema.

---

# 21. Request Headers

Mock APIs can define expected request headers.

Example:

```http
Authorization: Bearer <token>
Content-Type: application/json
X-API-Key: test-key
```

The platform validates incoming requests according to the configured request definition.

---

# 22. Request Body Schema

POST, PUT, PATCH, and other applicable endpoints can define a request body schema.

Example:

```json
{
  "name": "John",
  "email": "john@example.com",
  "age": 25
}
```

The configured schema determines which fields and structures are expected.

---

# 23. Request Validation

Incoming requests are validated against the configured request schema.

For example, if the API expects:

```json
{
  "name": "John",
  "age": 25
}
```

and the client sends an invalid structure, the platform returns a validation error.

Example:

```text
422 Unprocessable Content
```

The response contains information about the validation failure.

# 34. Common Swagger Errors

## 401 Unauthorized

Possible causes:

* JWT token missing
* JWT token expired
* Invalid JWT token
* Protected endpoint accessed without authentication

Solution:

```text
Click Authorize
```

and authenticate again.

---

## 404 Not Found

Possible causes:

* Incorrect endpoint
* Incorrect API ID
* Mock API does not exist
* Dynamic mock endpoint is not configured

Verify the endpoint path in Swagger.

---

## 409 Conflict

Usually indicates duplicate data.

Example:

```text
Username already exists
```

or:

```text
Email already exists
```

---

## 422 Unprocessable Content

This occurs when the request does not match the expected request format.

Check:

* Required fields
* Field names
* Field types
* Request body format
* OAuth2 login form fields

For OAuth2 login, use:

```text
username
password
```

rather than sending a JSON login body.

---

## 500 Internal Server Error

Indicates an unexpected server-side error.

Check the FastAPI/Uvicorn terminal logs for the actual exception.

# 38. Troubleshooting

### FastAPI does not start

Check the virtual environment:

```powershell
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```powershell
pip install -r requirements.txt
```

Start using:

```powershell
python -m uvicorn app.main:app --reload
```

---

### MySQL connection error

Verify that MySQL is running and that the database configuration in `.env` matches the Docker/MySQL configuration.

---

### Redis connection error

Verify Redis is running:

```powershell
docker compose ps
```

Check Redis logs:

```powershell
docker compose logs redis
```

---

### Swagger is not loading

Verify FastAPI is running:

```text
http://127.0.0.1:8000
```

Then open:

```text
http://127.0.0.1:8000/docs
```
